# Claude activity panel

[English](README.md) | [한국어](README.ko.md) | **日本語**

**Claude は自分の質問にすべて答えたか? 実際に何を変えたのか?**

長いコーディングセッションでは、自分の質問が何ページもの出力に埋もれがちです。「完了しました」の一言だけでは、変更後のコードがどう動くのかも分かりません。このパネルは [Claude Code](https://claude.com/claude-code) を動かしているペインの横に表示され、ターンが終わるたびにこの二つの疑問に答えます。

- **Q&A チェック**: そのターンで送った質問と依頼をすべて拾い出します。Claude の作業中に送ったメッセージも対象です。Claude が実際に答えた内容と行った作業をもとに、各項目を「回答済み / 一部回答 / 未回答」で判定し、足りない部分をハイライトします。未解決の項目は、後のターンで答えが出た時点で再チェックして更新します。状態の変更やアーカイブは、ページ上でも `claude-qa` コマンドでもできます。未解決の項目で **⧉ 質問をコピー** を押すと、同じことを聞き直すメッセージがコピーされるので、そのまま Claude に貼り付けられます。
- **ロジックフロー**: ファイルを編集したターンが終わると、変更された機能を実行順にたどって見せます。ステップのパイプライン、各ステップの役割と変更点、変更行をハイライトした実際のコード、変更したファイル、実行した検証が表示されます。
- **リアルタイム**: Claude が呼び出すツール (実行中、成功、失敗、所要時間) と変更したファイルを、その場で表示します。

パネルの表示と分析結果は、英語、韓国語、日本語に対応しています。

## 対応ターミナル

| ターミナル | Claude の横に開くもの | `claude-panel` で隠せる | テスト |
|---|---|---|---|
| [cmux](https://cmux.dev) | パネル全体 (フロー、リアルタイム、Q&A) をブラウザ split で | はい | 済み |
| Orca | パネル全体をブラウザタブで | いいえ | 未 |
| Ghostty 1.3 以上 | リアルタイム画面を split で。フローと Q&A は `claude-flow` で開く | はい | 済み |
| iTerm2 | リアルタイム画面を split で。フローと Q&A は `claude-flow` で開く | はい | 未 |
| その他 (VS Code、Terminal.app、tmux、Warp など) | 自動では何も開きません。`claude-panel` はブラウザでパネルを開き、`claude-activity` はどのターミナルでもリアルタイム画面を表示します | - | 済み |

Ghostty と iTerm2 は AppleScript で操作するため、最初に一度だけ macOS が操作の許可を求めます。

ほかのターミナルを追加するには [terminals/README.md](terminals/README.md) を見てください。小さなシェルファイル一つで済みます。

## 必要なもの

macOS、Claude Code、`jq`、`curl`、`/usr/bin/python3` (3.9 以上、標準ライブラリのみ。`xcode-select --install` で入ります)、zsh。

## インストール

```sh
git clone https://github.com/wonjoonSeol-WS/claude-side-insights.git ~/.claude/activity-panel
~/.claude/activity-panel/install.sh
```

`install.sh` が行うのは次の三つです。

- `~/.claude/settings.json` に hook を追加します (足りないものがある場合だけ。先に同じ場所にバックアップを残します)。
- `~/.zshrc` の末尾に目印付きのブロックを追記します。
- `claude-panel`、`claude-flow`、`claude-qa`、`claude-activity` を `~/.local/bin` に置きます。

何度実行しても結果は変わりません。

## コマンド

ターミナルで実行するか、Claude Code 内では先頭に `!` を付けて実行します (例: `! claude-panel`)。

| コマンド | 内容 |
|---|---|
| `claude-panel` | このペインのパネルを表示 / 非表示 ([対応ターミナル](#対応ターミナル) を参照) |
| `claude-flow` / `claude-flow all` | このペインのパネル / すべてのパネルの一覧を既定のブラウザで大きく開く |
| `claude-qa list [--open]` | 現在のセッションの質問を id と状態付きで表示 |
| `claude-qa set <id> answered\|partial\|unanswered\|auto` | 状態を手動で指定 (`auto` でモデルの判定に戻す) |
| `claude-qa archive <id>` / `restore <id>` | 項目をアーカイブ / 復元 |
| `claude-activity` | リアルタイム表示をこのペインのターミナル UI で見る |

パネル内のショートカット: `1` `2` `3` でフロー、リアルタイム、Q&A を切り替え、`←` `→` でフローのステップを移動、`?` ですべてのコマンドと設定をまとめたヘルプを開き、`Esc` で閉じます。

## 設定

パネル右上の **⚙ 設定** から変更します。変更は `~/.claude/activity-panel/config.json` に保存され、次の分析から反映されます。再起動は不要です。

**適用範囲** で **すべてのパネル** を選ぶと既定値が変わり、**このパネルのみ** を選ぶと、このペイン (とそこで動く Claude セッション) にだけ別の値を使います。たとえば、あるペインは日本語、別のペインは韓国語にできます。パネルごとに指定した値は設定画面に表示され、全体の設定に戻すこともできます。

| 設定 | 既定値 | 意味 |
|---|---|---|
| 分析モデル | `opus` | `opus`、`sonnet`、`haiku` (完全なモデル id は config.json で指定) |
| 言語 (画面と分析) | `en` | English、한국어、日本語 |
| ターン終了時にフローを作成 | オン | オフにすると ↻ ボタンでのみ作成 |
| ターン終了時に Q&A をチェック | オン | オフにすると ↻ ボタンでのみチェック |
| セッション開始時にパネルを開く | オン | オフにすると `claude-panel` でのみ開く |

環境変数は `CLAUDE_PANEL_PORT` (既定 `47821`) だけです。

## よくある質問

**Claude の呼び出しは何回増えますか?**
1 ターン終わるごとに最大 2 回です。Q&A チェックが毎ターン 1 回、そのターンでファイルを編集していればロジックフローがもう 1 回です。リアルタイム表示、状態の変更、アーカイブでは呼び出しません。`!` のシェルコマンドはターンではないので、何も動きません。↻ ボタンは押すたびに 1 回呼び出します。

**コストはどのくらいですか?**
これまでの実測値は、Q&A チェックが Opus で $0.04 ~ $0.11、ロジックフローが Sonnet で $0.16 ~ $0.17 です (Opus は未計測)。フローは読むコードが多いほど高くなります。これは Claude Code が表示する定価ベースの見積もりです。サブスクリプションでは金額ではなく利用上限にカウントされると思われますが、確認はしていません。抑えたい場合は、モデルを `sonnet` か `haiku` に変えるか、自動実行をオフにしてください。

**Claude は毎ターン HTML を作るのですか?**
いいえ。ページのテンプレートは一つだけです。分析が JSON を返し、ページがそれを描画します。

**↻ フローを作り直す、↻ 未解決を再チェック、↻ この質問を再チェックもエージェントを呼び出しますか?**
はい。自動実行と同じ headless `claude -p` を起動し、コストも同じです。この実行はファイルを読むだけで、編集やコマンドの実行はできません。

**作業中のセッションが遅くなったり、コンテキストが増えたりしませんか?**
しません。分析はターン終了後に別プロセスで動き、セッションのコンテキストには何も追加しません。

**ロジックフローはコードのロジックを追うのにも使えますか?**
それが本来の用途です。変更された機能を実行ステップに分けて示し、現在のファイルから実際のコードを抜き出して見せます。自動で動くのはファイルを編集したターンだけなので、説明だけのターンでは ↻ を押してください。

**後のターンで答えてもらったのに、まだ「一部回答」と表示されます。**
チェックは、前回のチェック以降の会話をすべて対象にします。Claude の作業中に送ったメッセージも含まれます。同じセッションの以前のターンに残っている未解決の項目 (最大 60 件) も新しい回答と照らし合わせ、答えが出ていれば状態を更新します。それより古い項目は、上部の **↻ 未解決を再チェック** (今のページにあるターンの未解決の質問を最大 40 件まとめて再判定) か、項目ごとの **↻ この質問を再チェック** を押すか、状態を手動で変更してください。チェックに失敗したターンには **↻ このターンを再チェック** ボタンが表示されます。

**パネルを隠したり、オフにしたりするには?**
`claude-panel` で表示と非表示を切り替えます。自動で開かないようにするには「セッション開始時にパネルを開く」をオフにします。完全に削除するには `uninstall.sh` を実行します (`--purge` を付けると記録したデータと設定も消えます)。

**データはどこに保存されますか?**
`~/.claude/activity-panel/` の下です。

- `config.json`: 設定
- `token`: パネルのページと `claude-qa` がサーバーに送る秘密の値
- `logs/`: ツールの活動
- `turns/`: ペインごとの、今のターンが始まった位置
- `flows/`: ロジックフロー
- `qa/<ペイン>/<セッション>/`: Q&A (セッションごとに保存)
- `qa/<ペイン>/overrides.json`: 手動で変えた状態

どれも git にはコミットされません。ペインごとのページは `http://127.0.0.1:47821/p/<ペイン>?t=<トークン>`、すべてのペインの一覧は `http://127.0.0.1:47821/?t=<トークン>` です。`claude-flow` で開くとトークンは自動で付きます。

## 仕組み

```
Claude Code hooks ──► record.sh ──► logs/<pane>.jsonl ──┐
   (ツール呼び出し、依頼、ターン終了)                   ├─► server.py (127.0.0.1:47821) ──► ブラウザペインの app.html
Stop hook ──► flow.py / qa.py ──► flows/, qa/ (JSON) ───┘
                 └─ headless `claude -p` (読み取り専用ツール、MCP サーバーと hook なし)
```

- リアルタイム表示にコストはかかりません。hook が JSON を 1 行ずつ記録し、ページが 1 秒ごとにローカルサーバーから読み込みます。
- フローと Q&A は、ターン終了後にそれぞれ別の headless `claude -p` として動くので、作業中のセッションのコンテキストには触れません。フローはファイルを編集したターン (Edit/Write、またはファイルを書き込むシェルコマンド) でだけ動き、Read/Grep/Glob でコードを読めます。Q&A が読むのは会話のテキストと Claude が使ったツールの一覧だけで、ファイルは読みません。
- パネルのキーはターミナルが提供するペイン id ([対応ターミナル](#対応ターミナル) を参照)、なければセッション id です。Q&A はセッションごとに保存され、表示されるのは現在のセッションの分だけです。

## データとプライバシー

データはすべて手元のマシンに、自分のユーザーだけが読めるファイルとして保存されます。サーバーは 127.0.0.1 でのみ待ち受け、宛先が `127.0.0.1` か `localhost` のリクエストしか受け付けないため、Web ページが DNS rebinding で到達することはできません。さらに、どのページも URL に、どの API リクエストも `X-Claude-Panel` ヘッダーに `~/.claude/activity-panel/token` のトークンが必要です。そのため、他の Web ページや同じマシンの他のユーザーが、活動の記録を読んだり、設定を変えたり、有料の分析を実行させたりすることはできません。

## アンインストール

```sh
~/.claude/activity-panel/uninstall.sh          # 記録したデータと設定は残す
~/.claude/activity-panel/uninstall.sh --purge  # それも削除
```
